## How to read this

**Who can see a tab** — shorthand used in every table:

| Term | Meaning today |
| --- | --- |
| **all** | Any signed-in, active login (`requireSession`). Nothing narrower. |
| **M:x** | Holds module `x` (`requireModule`). The owner holds every module. Modules: `calendar`, `customers`, `pos`, `services`, `payroll`, `reports`, `team`, `audit`, `settings`. |
| **owner** | The salon's owner role (`session.isOwner`, `assertRole(..., "owner")`). |
| **front desk\*** | Legacy `profile.role` is `owner` or `receptionist`. Not a module. See D1. |
| **own** | A therapist's rows only, enforced by RLS (`staff_id = current_team_member_id()`), whatever their role holds. |

Hiding a tab is a courtesy. The page guard, the action guard and RLS stay as they are and remain the security boundary (`CLAUDE.md` › Conventions). `DESIGN.md`: a tab a role cannot use is not rendered.

**Section column**: what the page renders today. **Gap column**: mockup elements for that tab with no backing (copied into `docs/mockup-gaps.md`). "Page data" means the element is built only from rows the page already loads.

**Role names.** Mockup roles (Owner, Manager, Front desk, Therapist) are sample names. The app's built-in roles are **Owner**, **Staff / Therapist**, **Receptionist** and **Accountant**; salons add their own. Tabs here are gated by module, never by role name.
